给业务合伙人的项目准备清单 · 2026-08-08

Shopify Headless
独立站准备清单

目标是用 Next.js 建立独立前端并部署在自己的云服务器上，同时使用 Shopify 管理商品、库存、订单和结账。首版采用“标准商品在线下单 + 定制加工 RFQ 询价”。

前端Next.js + 独立云服务器
电商后台Shopify Storefront/Admin API
首发市场美国，USD

一、先对齐系统边界

Shopify 不是被替换，而是作为电商后台。

客户看到的是独立部署的 Next.js 网站；商品、库存、订单、客户、优惠和最终结账仍由 Shopify 提供。独立后端负责 RFQ、型材配置、报价、文件上传和业务系统对接。

模块首版由谁负责准备内容
品牌页面、产品页、应用页Next.js前端页面、SEO、响应式设计、内容数据
商品、库存、价格、订单Shopify产品、变体、价格、库存地点、订单流程
购物车和付款ShopifyStorefront API、Cart、Checkout URL、支付配置
定制切割和批量采购独立后端RFQ 表单、附件、报价状态、Draft Order
ERP、仓库、物流第二阶段API、Webhook、库存同步和发货状态
架构建议：前端可以放在独立云服务器；数据库建议使用托管 PostgreSQL，避免把网站和数据库放在同一台机器上。Cloudflare 放在前面做 DNS、CDN 和基础防护。

二、业务合伙人必须提供的资料

公司与商业

  • 公司中英文名称、地址和主体资料
  • 英文品牌名、域名候选和 Logo
  • 目标客户类型和首发应用场景
  • 目标国家、币种和售后范围
  • 客服邮箱、电话、WhatsApp

供应链与履约

  • 工厂、仓库和发货地
  • 生产/加工能力与月产能
  • MOQ、交期、包装和破损处理
  • 短料快递、长料货运报价
  • 美国进口商和税费承担方案

三、首发产品清单

不要先导入完整目录。先选一个场景、一个单位体系和 10-20 个 SKU。

产品类别首版建议交易方式

应用套件工作台、设备机架、机器防护基础套件购买或询价
定制型材切割、钻孔、攻牙、BOM 齐套RFQ

每个 SKU 必须提供

  • 英文名称、SKU、系列和应用
  • 截面尺寸、槽宽、合金/状态
  • 表面处理、颜色和单位重量
  • 标准长度、切割范围和公差
  • 单价、数量价和加工费
  • 库存、交期和可配送区域
  • 净重、包装尺寸和装箱数量
  • 白底图、细节图、场景图
  • 截面图、PDF、STEP、DXF
  • 兼容配件和安装说明

五、Next.js 与独立服务器准备

开发环境

  • GitHub/GitLab 代码仓库
  • Node.js LTS、包管理器和环境变量管理
  • 开发、预发布、生产三套环境
  • CI/CD 自动构建和部署

服务器环境

  • Linux 云服务器，建议 2 vCPU / 4 GB 起步
  • Docker、Nginx 或 Caddy
  • Cloudflare DNS、CDN 和 WAF

  • 独立 PostgreSQL、对象存储和 Redis（按需）

需要申请的 Shopify 开发资料

  • Storefront API token 和 API 版本
  • Admin API 自定义应用及最小权限
  • Webhook：订单、库存、产品和履约状态
  • Shopify 店铺域名和 Checkout 配置
  • 测试商品、测试订单和测试客户

页面功能

资源页选型指南、安装说明、FAQ、CAD 下载
账户与订单订单查询、邮件通知、客服入口

六、RFQ 与业务后端

RFQ 是首版最重要的自定义功能。

不要一开始开发复杂的实时配置器。先让客户提交完整需求，业务人员审核后在 Shopify 创建 Draft Order 并发送付款链接。

RFQ 表单字段

  • 姓名、公司、邮箱、电话
  • 配送国家、州/省和邮编
  • 型材系列、截面、长度和数量
  • 合金、表面处理和颜色
  • 切割、钻孔、攻牙要求
  • 目标交期和项目说明
  • PDF、DXF、STEP、BOM 上传
  • 是否需要连接件和面板
  • 税费/货运报价要求
  • 同意隐私和报价条款

后端交付物

模块首版要求后期再做
RFQ 管理收件、附件、状态、负责人、邮件通知自动分配、SLA 和报表
报价人工核价、Draft Order、付款链接自动计算长度、加工和运费
文件病毒扫描、权限控制、过期链接CAD 转换和在线预览
库存Shopify 作为首版库存来源ERP/MES/WMS 双向同步
安全限流、日志、备份、管理员权限审计、风控和高级告警
文件上传不要直接暴露服务器目录。使用对象存储的私有 Bucket、短时签名链接和访问日志。

七、支付、物流与合规

支付验收

  • 信用卡和 PayPal 测试付款
  • 退款、取消和拒付处理
  • 支付失败后的订单状态
  • 邮件和客服通知
  • 管理员双重验证

物流验收

  • 包装后重量和尺寸
  • 短料、长料和超长件报价
  • 不同美国邮编测试
  • DDP/DAP 和税费表达
  • 破损、补发和退件流程

必须发布的页面

  • Shipping Policy
  • Return & Refund Policy
  • Privacy Policy
  • Terms of Service
  • 定制品取消和退货规则
  • 税费和进口责任说明
  • 公司和客服信息
  • Cookie 和数据说明

八、项目实施顺序

1

业务资料冻结

确定场景、SKU、价格、交期、物流和售后规则。

2

Shopify 配置

创建店铺、支付、产品、库存、政策和测试订单。

3

Next.js 基础站

完成首页、产品页、应用页、资源页和响应式体验。

4

API 与 Checkout

接 Storefront API、购物车、Checkout、订单和 Webhook。

5

RFQ 后端

完成询价、附件、邮件、报价状态和 Draft Order。

6

服务器上线

完成域名、Cloudflare、部署、监控、备份和回滚。

7

真实交易验收

测试付款、退款、运费、RFQ、移动端和订单通知。

项目验证期参考说明

云服务器和数据库USD 30-200/月可从小规格开始，数据库建议托管

十、上线验收清单

业务

  • 10-20 个 SKU 信息准确
  • 价格、交期、运费已确认
  • RFQ 负责人和响应时间明确
  • 退货、定制和税费规则发布
  • 首批客户和获客渠道已准备

技术

  • 开发/预发布/生产环境分离
  • API Token 不进入前端代码
  • 支付、退款和 Webhook 正常
  • 备份、监控和回滚可用
  • 移动端、SEO 和性能达标

十一、双方现在需要确认的 10 项

  1. 英文品牌名和域名
  2. 公司主体、收款主体和银行账户
  3. 首发客户类型和应用场景
  4. 10-20 个首发 SKU
  5. 产品价格、规格、图片和 CAD
  6. 库存地、发货地和交期
  7. 短料/长料物流报价规则
  8. 在线购买与 RFQ 的边界
  9. 首版预算和上线日期
  10. 业务合伙人、技术、运营、客服负责人

最终建议：先做标准商品在线购买 + RFQ，再根据真实询价量开发自动配置器。Headless 的价值在于可以逐步增加业务能力，而不是第一天把所有功能做完。
